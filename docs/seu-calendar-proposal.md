# 东南大学宣讲会日历接入方案（已确认）

## 目标

日历中的宣讲会以 https://career.seu.edu.cn/frontpage/seu/html/recruitmentFairList.html 为唯一自动来源。显示按北京时间计算的今天及未来活动；邮件中的宣讲会不再显示或新建。手动事项和其他邮件事项保留。

## 已核实的公开数据

- 页面通过 POST /f/recruitmentFair/ajax_frontRecruitfair 查询公开活动，支持 pageNo/pageSize。
- 数据有活动稳定 id、title、startTime、endTime、place/field.name、校区及详情 url。
- 2026-10-11 只读核验共 6 页、516 条，开始日期为当天及未来的 110 条；当天 0 条，最晚 2026-10-27。
- 首页有开始日期已过的置顶活动，不能遇到旧日期就提前停止分页。

## 推荐行为

1. 启动时刷新，可手动刷新；完整读取分页后才更新缓存，网络失败沿用上次成功结果并显示状态。
2. 活动按网站 id 去重，按网站开始日期放进日历，显示原始标题、起止时间、校区地点及官网详情链接。
3. 官网活动使用独立缓存和来源标识，作为只读日程展示；现有待办仍可编辑、勾选和删除。官网日程不按未完成待办滚动到后续日期。
4. 今天列表显示当天官网日程，日历显示当天和未来官网日程。过去官网日程不展示。
5. 新旧邮件宣讲会均在视图中过滤，历史记录不删除。新扫描遇到宣讲会不创建事项；同邮件其他面试、笔试等活动仍创建。
6. 不把招聘流程里的“宣讲”字样一概当作宣讲会；旧版邮件仅识别明确的宣讲会类型标记。
7. 官网变更反映到下一次成功刷新；取消/移除活动不再出现在当前快照中，不清理用户原始待办。

## 验证要求

- 北京时间今天边界、昨天排除、跨月未来活动、所有分页、重复 id、非法时间、相同公司不同场次。
- 邮件宣讲会在两个视图过滤；同邮件其他事项不受影响，手动宣讲事项保留。
- 官网日程只读，来源标签及详情链接正确；网络失败有状态且保留成功缓存。
- 现有 Rust/Vue 测试、前端构建、发布构建、隔离启动验证，随后保留旧程序备份并更新运行版本。

## 备选

- 一次性导入：改动少，但网站变更后需要重新导入，不推荐。
- 推荐上述独立官网日程来源：避免官网活动与个人待办的完成、编辑和滚动规则混在一起。
